# Panduan Build Windows — Chat to PDF (Fase 5)

Sandbox pengembangan adalah Linux; installer NSIS (.exe) **harus di-build di mesin Windows**.
Sebagian besar artefak sudah di-stage di repo — di Windows hanya perlu beberapa langkah.

## Jalur CI otomatis (disarankan)

`.github/workflows/build-windows.yml` menjalankan **semua langkah di bawah** di `windows-latest`:
build NSIS → install silent (`/S`) → uji E2E (UI, generate PDF, TOC, license, lifecycle, metrik
startup) → upload artefak (`chat2pdf-setup`, `e2e-evidence`: screenshot, PDF, tasklist, summary).
Trigger: push ke `main` atau `baseline/working-copy` (path client/server/src-tauri/e2e) atau
manual (`workflow_dispatch`). Prasyarat: set GitHub Secret `LICENSE_SECRET` (Settings → Secrets
→ Actions, nilai sama persis dengan `server/.env` lokal) **sebelum** push/Run — `.env` disuntik
saat runtime CI dan hanya berisi `LICENSE_SECRET` (DATABASE_URL dibiarkan di-resolusi
`ensureDatabaseUrl()` ke `resources/prisma/dev.db` di path ter-instal).
Catatan push: sidecar Express Windows (127 MB) **melebihi batas file GitHub (100 MB)** sehingga
tidak ikut branch `baseline/working-copy` (orphan, 1 commit) — workflow CI membangunnya sendiri
dengan pkg (`server` → `npx pkg@6.26.0 --target node24-win-x64`), prosedur sama dengan lokal.

## Langkah di mesin Windows

1. **Prasyarat**: Rust stable (`rustup`), Node 24, `npm i -g @tauri-apps/cli@2` (plus VS Build Tools — menyediakan `rc.exe` untuk tauri-winres; di Linux cross-check ini jadi blokir karena butuh `llvm-rc`).
2. **`.env` resource WAJIB ada sebelum `tauri build`** — tauri-build memvalidasi keberadaan semua
   path yang dideklarasikan di `bundle.resources` (terbukti: `resource path 'resources/.env' doesn't exist`
   menggagalkan build). File ini sengaja tidak di-commit (gitignore). Salin:
   ```powershell
   Copy-Item server\.env src-tauri\resources\.env
   ```
3. **Engine Prisma Windows** (tak bisa diunduh dari sandbox — CDN menolak fetch eksternal):
   ```powershell
   cd server
   npm ci
   Copy-Item node_modules\.prisma\client\query_engine.dll.node ..\src-tauri\resources\prisma\
   ```
   (nama file bisa `query_engine.dll.node` atau `query-engine.dll.node` — keduanya dikenali
   oleh `server/src/lib/runtime-paths.js`).
3. **Validasi binary Express di Windows** (opsional tapi disarankan):
   ```powershell
   cd server\dist
   # salin resources di samping binary (layout sama seperti uji Linux), lalu:
   $env:PORT = "0"; .\express-server.exe   # harus mencetak READY_PORT=<port>
   curl http://localhost:<port>/api/health  # 200
   ```
4. **Build installer**:
   ```powershell
   cd client && npm ci && npm run build
   cd ..\src-tauri
   npx tauri build
   # hasil: src-tauri\target\release\bundle\nsis\Chat to PDF_1.0.0_x64-setup.exe
   ```
5. **Uji E2E** (checklist Fase 5C): UI muncul di WebView → generate PDF → license verify →
   tutup aplikasi → pastikan proses `express-server.exe` dan `typst.exe` hilang dari Task Manager.

## Catatan teknis

- **Kode aplikasi sudah tervalidasi terhadap target Windows**: `main.rs` (verbatim) lolos
  `cargo check --target x86_64-pc-windows-msvc` (exit 0, 0 error) — termasuk ekspansi makro
  `generate_context!` yang memvalidasi tauri.conf.json + ikon, dan seluruh dependency graph
  Windows (tauri 2.12.7, tauri-plugin-shell 2.6.0, webview2/windows-sys). Type-check ini
  dijalankan di crate scratch tanpa `tauri-build` karena `tauri-build` menuntut compiler
  resource Windows (`rc.exe` di host Windows / `llvm-rc` di host Linux) — di mesin Windows
  dengan VS Build Tools, langkah ini otomatis tersedia.
- `tauri.conf.json` VALID terhadap JSON Schema resmi Tauri 2 (`schema.tauri.app/config/2`);
  `capabilities/default.json` VALID terhadap schema ACL tauri-plugin-shell 2.6.0
  (`shell:allow-execute`/`shell:allow-spawn` + entri sidecar diperiksa terhadap
  `permissions/autogenerated/commands/{execute,spawn}.toml`).
- Signature API yang dipakai `main.rs` (diperiksa per-signature terhadap source crate):
  `sidecar()`, `Command::env()`, `spawn() -> (Receiver<CommandEvent>, CommandChild)`,
  `CommandChild::kill(mut self)`, `RunEvent::Exit`, `tauri::Url`, `resource_dir()`,
  `executable_dir()`, `WebviewWindowBuilder::new(manager, label, WebviewUrl)`.
- Saat exit, `RunEvent::Exit` memanggil `child.kill()` pada sidecar Express (typst adalah
  child dari Express, ikut mati; sebagai jaring pengaman Express juga mengirim `SIGKILL`
  timeout 30s per compile).
- Flash console window pada sidecar Windows: jika muncul, tambah `windows_subsystem`/window
  hide pada spawn (polish, tidak mengubah fungsionalitas).

> Catatan: `src-tauri/resources/.env` tidak di-commit (pola `.env` di `.gitignore` root).
> Salin manual dari `server/.env` saat build Windows (langkah 2 di atas).
